We can generate the topology (topology.yml) using natural language, it's entities (functions etc) or IAC using LLMs.

Usage:
```sh

tc scaffold --topology [--model <model-id> --skills skills/topology.md]
tc scaffold --iac tf|boto|rust|aws-cli [--model <model-id> --skills skills/iac.md]
tc scaffold --entity functions  [--model <model-id> --skills skills/functions.md]
```

## Scaffold topology.yml

```sh
tc scaffold --topology
> Architecture Description: Generate a topology to compute sum of two numbers. Notify result via channel
```
This generates a topology.yml, in the current directory,  with a high-level abstract structured representation of the topology without leaking any of the infrastructure-specific components in it.

We can also specify a skills file for the topology. It defaults to ./skills/topology.md. This skill or spec could contain a more elaborate description of the topology.


## Scaffold IaC

tc's goal is not be a deployer in the future. Instead use it's compositional feature to generate IAC that can be audited and have a lifecycle of it's own. tc does best effort to instruct LLMs to conform to the Topology spec and honor it's boundaries. In doing so, LLMs are able to generate meaningful infrastructure code that can rendered in any sandbox, account or region.

To generate Terraform code:

```
tc scaffold -e dev --iac tf --out-dir tf [--skills skills/iac.md]
```

We can override the skills required to generate IAC using the ./skills/iac.md file.

To generate CDK

```
tc scaffold -e dev --iac cdk --out-dir cdk
```

Other available iac options: boto, go, rust, aws-cli


## Scaffold entities

```sh
tc scaffold --entity functions
```
This scaffolds the function directories and function specs.
